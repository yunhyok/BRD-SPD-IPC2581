BRD-SPD-IPC2581
Allegro plane 반영 안내

SPD의 선택된 plane 형상을 기존 Allegro 보드에 반영하는 작업을 준비하고, 실행하고, 결과를 확인하는 방법입니다.

목차 시작하기 작업 방식 선택 대상 레이어·NET 선택 Native SKILL 생성 워크스테이션 Agent 원격: 새 Allegro 실행 원격: 기존 Allegro PID 결과와 다시 받기 문제 해결 지원 범위와 제한

시작하기

이 프로그램은 일반적인 SPD를 완전한 BRD로 재구성하지 않습니다. 같은 보드의 기존 BRD를 기준으로, 선택한 레이어와 net의 plane 형상을 반영해 별도의 결과 BRD를 만듭니다.

실행 전 준비: 원본 BRD와 수정 SPD가 같은 보드인지 확인하고, 원본을 별도로 보관하세요. 결과 BRD는 Allegro에서 열어 plane, void, net, DRC를 검토해야 합니다. 실행 직전에 SPD 수정 여부를 다시 확인한 뒤 출력 폴더의 상위 경로에 임시 SPD 사본을 만들고, 작업이 끝나면 제거합니다. 작업 중 필요한 사본 공간도 확보하세요.

메인 앱에는 Native SKILL 생성과 원격 Allegro 작업 탭이 있습니다. 두 탭 모두 SPD를 먼저 불러와야 대상 선택과 실행을 할 수 있습니다. IPC-2581 변환 기능은 현재 UI와 CLI에서 비활성화되어 있으며, 기존 백엔드 파일이 남아 있더라도 이 도움말의 작업 흐름에는 사용하지 않습니다.

작업 방식 선택

파일 생성만

Native SKILL 생성

노트북 또는 어느 PC에서나 SPD를 읽어 SKILL 번들을 만듭니다. 이 단계에서는 Allegro를 실행하지 않고 라이선스도 사용하지 않으며, PID가 필요 없습니다.

생성한 폴더를 라이선스 있는 워크스테이션으로 복사한 뒤 사용자가 명령을 실행합니다.

원격 실행·회수

원격 Allegro 작업

워크스테이션에서 Agent를 수동 시작하고, 노트북 앱이 인증된 연결로 파일을 전송합니다. Agent가 Allegro 실행 또는 선택한 기존 세션 제어와 결과 ZIP 회수를 담당합니다.

실행 PC에 Allegro 24.1과 라이선스가 있어야 합니다.

선택 기준: 네트워크를 쓰지 않고 검토 가능한 스크립트만 원하면 Native SKILL을, 노트북에서 작업 상태·로그·결과 ZIP을 관리하려면 원격 Allegro 작업을 사용합니다.

대상 레이어·NET 선택

두 주요 탭에서 SPD를 먼저 불러온 다음 대상 레이어 (빈칸: 전체), 대상 NET (빈칸: 전체) 옆 목록에서 선택… 버튼을 사용합니다.

먼저 SPD 불러오기

  1. SPD 입력의 찾아보기…로 파일을 선택하면 자동으로 읽습니다.
  2. 경로를 직접 입력했거나 저장되어 있던 경로를 쓰려면 SPD 불러오기를 누릅니다.
  3. 큰 파일은 백그라운드에서 읽으며 진행 상태가 표시됩니다. 로딩이 성공하기 전에는 레이어/NET 입력과 목록 선택, 부품 위치/회전 옵션, SKILL 번들 생성 또는 원격 실행이 비활성화됩니다.
  4. SPD 파일 경로를 바꾸면 기존 레이어, NET, 부품 옵션 선택은 초기화됩니다. 새 파일을 다시 SPD 불러오기한 뒤 범위를 정합니다.

연결 확인, PID 확인, 기존 작업 받기와 도움말은 SPD를 불러오기 전에도 사용할 수 있습니다.

  1. 목록 창은 이미 읽은 SPD의 미리 읽은 목록을 사용합니다. 파일을 바꾸면 목록은 다시 읽으며, 같은 파일도 수정 시간이 바뀌면 이전 목록을 사용하지 않습니다.
  2. 레이어 창에서 Ctrl 또는 Shift를 사용해 여러 항목을 선택합니다. 전체 선택, 선택 해제, 적용, 닫기를 사용할 수 있습니다. 선택 창이 열린 동안에는 현재 탭의 범위와 실행을 바꿀 수 없습니다.
  3. 레이어를 적용한 뒤 NET을 선택하려면 목록에서 선택…을 다시 엽니다. NET 목록은 현재 선택한 레이어에 있는 지원되는 plane의 NET만 보여 줍니다.
  4. NET도 Ctrl 또는 Shift로 여럿 선택하고 적용합니다. 선택 없이 적용할 수는 없습니다. 입력칸을 빈칸으로 만드는 전체 대상 의미와 혼동하지 않도록 한 동작입니다.
목록에 보이지 않는 항목: trace/via만 있는 NET, dielectric, 지원되는 plane이 없는 레이어는 native plane 갱신 대상이 아니므로 목록에 나타나지 않습니다. 입력칸을 비워 두면 현재 SPD에서 지원되는 plane 전체가 대상입니다. 전체 선택은 그 목록의 모든 항목을 입력칸에 넣습니다.

직접 입력도 유지됩니다. 쉼표로 값을 구분하며 CSV 따옴표를 쓸 수 있습니다. 다만 이름의 공백·기호와 현재 레이어 조건을 안전하게 반영하려면 목록 선택을 우선 사용하세요. 레이어 선택을 바꾼 뒤에는 NET 목록을 다시 확인하세요.

Native SKILL 생성과 수동 실행

이 탭은 실행하지 않고 새 번들 폴더만 만듭니다. Allegro PID는 사용하지 않습니다.

앱에서 번들 만들기

  1. SPD 입력에서 수정 SPD를 찾아보기…로 고르거나 경로를 입력한 뒤 SPD 불러오기를 누릅니다. 성공할 때까지 이후 선택과 생성은 사용할 수 없습니다.
  2. 새 번들 출력 폴더에 아직 존재하지 않는 새 경로를 지정합니다. 기존 폴더에는 생성할 수 없습니다.
  3. 필요하면 대상 레이어 (빈칸: 전체), 대상 NET (빈칸: 전체) 옆 목록에서 선택…으로 범위를 정합니다. 직접 쉼표 입력과 CSV 따옴표도 가능하지만 목록 선택을 권장합니다. 비워 두면 지원되는 SPD plane 전체가 대상입니다.
  4. 기존 부품 위치/회전 데이터 포함은 이미 배치된 부품의 위치·회전만 갱신합니다. 부품을 새로 만들거나 삭제하지 않습니다.
  5. SKILL 번들 생성을 누르고, 로그와 generation.report.json을 검토합니다.

워크스테이션에서 수동 실행

중요: 이 방식의 생성된 배치 스크립트는 이미 열려 있는 사용자 Allegro 세션에 load하지 않습니다. 아래처럼 별도 배치 Allegro를 실행합니다.
  1. 생성한 번들 폴더 전체를 라이선스가 있는 워크스테이션으로 복사합니다.
  2. 같은 보드의 원본을 복사해 번들 폴더 안에 base.brd라는 이름으로 둡니다. 원본 파일 자체를 이동하거나 이름 변경하지 마세요.
  3. PowerShell을 열고 현재 작업 폴더를 번들 폴더로 옮긴 뒤 다음을 실행합니다.
Set-Location 'C:\작업\native-job'
& 'C:\Cadence\SPB_24.1\tools\bin\allegro.exe' -nograph -s run.scr base.brd

배치 실행은 성공 시 result.brd를 별도로 저장한 뒤 Allegro를 종료합니다. 성공으로 판단하려면 Allegro 종료 코드가 0이고, result.json의 상태가 success이며, result.brd가 비어 있지 않은지 함께 확인하세요. 실패 시 execution.log과 result.json을 확인합니다.

워크스테이션 Agent 시작

라이선스와 Allegro가 설치된 Windows 워크스테이션에서만 BRD-SPD Workstation Agent를 수동 실행합니다. 설치 프로그램이나 Agent는 방화벽 규칙과 자동 시작 설정을 바꾸지 않습니다.

  1. 바인드 주소를 정합니다. 모든 네트워크 인터페이스에서 받으려면 0.0.0.0을 입력합니다. 이것은 Agent가 듣는 주소이며, 노트북에 입력하는 주소가 아닙니다.
  2. 포트는 기본값 8765를 사용하거나 조직 정책에 맞는 값을 지정합니다.
  3. 허용 클라이언트 IP (선택)에는 접속을 허용할 노트북의 IP 주소를 입력합니다. 여러 개는 쉼표로 구분합니다.
  4. Allegro 실행 파일은 기본 C:\Cadence\SPB_24.1\tools\bin\allegro.exe를 확인하거나 실제 설치 경로로 바꿉니다.
  5. 작업 폴더는 Agent가 전송 파일과 작업 결과를 보관할 로컬 폴더입니다. 결과와 백업, 로그를 둘 충분한 디스크 공간을 확보합니다.
  6. Agent 시작을 누릅니다. 표시되는 토큰과 인증서 지문을 노트북에 안전하게 옮깁니다. 토큰은 클라이언트에 저장되지 않으므로 앱을 다시 열면 다시 붙여 넣습니다.
노트북에 넣을 IP: 예를 들어 Agent가 0.0.0.0에 바인드되어도 노트북의 워크스테이션 IP에는 실제 워크스테이션의 연결 가능한 주소를 입력합니다. 문서 예시 주소는 192.0.2.16이며 실제 환경 주소가 아닙니다.

원격 작업: 새 Allegro 실행

PID를 비워 두면 Agent는 전송된 원본 BRD로 별도 Allegro 작업을 실행합니다. 이 방식은 현재 열려 있는 사용자 Allegro 창을 대상으로 하지 않습니다.

원격 Allegro 작업 탭 입력
워크스테이션 IP / 포트예: 192.0.2.16, 기본 포트 8765. Agent 화면의 실제 연결 가능한 워크스테이션 주소를 씁니다.
접속 토큰 / 인증서 지문Agent 시작 후 표시된 값을 그대로 입력합니다. 토큰을 로그, 캡처, 공유 문서에 남기지 마세요.
Allegro PID (빈칸: 새 실행)빈칸으로 둡니다.
SPD 입력 / 원본 BRD수정 SPD와 같은 보드의 원본 BRD를 모두 선택합니다.
출력 ZIP아직 없는 새 ZIP 파일 경로를 지정합니다. 기존 ZIP은 덮어쓰지 않습니다.
대상 레이어 (빈칸: 전체) / 대상 NET (빈칸: 전체)목록에서 선택…으로 선택 범위를 정하는 것을 권장합니다. 직접 쉼표 입력과 CSV 따옴표도 가능하며, 빈칸이면 지원되는 SPD plane 전체입니다.
  1. 연결 확인으로 토큰, 인증서, 네트워크 상태를 먼저 확인합니다. 이는 SPD를 불러오기 전에도 할 수 있습니다.
  2. SPD 입력에서 찾아보기…로 선택하거나 경로 입력 뒤 SPD 불러오기를 누릅니다. 성공한 뒤에만 범위, 부품 옵션, 전송 및 실행이 활성화됩니다.
  3. 필드를 채운 뒤 전송 및 실행을 누릅니다. 업로드와 실행 상태는 원격 작업 로그에서 봅니다.
  4. 완료되면 새 출력 ZIP을 받습니다. 작업 ID를 보관하면 앱을 다시 열어도 기존 작업 받기로 상태와 결과를 조회할 수 있습니다.

원격 작업: 기존 Allegro PID

현재 열려 있는 설계에 반영하려면 워크스테이션의 Allegro PID를 명시합니다. PID는 PowerSI나 노트북 프로세스의 PID가 아니라 워크스테이션 작업 관리자의 allegro.exe PID입니다.

  1. 워크스테이션에서 대상 BRD를 Allegro로 열고, 진행 중인 명령과 모달 대화상자를 모두 마칩니다. 작업 중에는 그 창을 직접 편집하지 마세요.
  2. 작업 관리자의 세부 정보에서 대상 allegro.exe PID를 확인합니다.
  3. 노트북 앱의 Allegro PID (빈칸: 새 실행)에 양의 정수를 입력하고 PID 확인을 누릅니다. 표시된 실행 파일과 생성 시각이 의도한 창인지 확인합니다.
  4. SPD 입력을 찾아보기…로 고르거나 경로를 입력한 뒤 SPD 불러오기를 누릅니다. 새 출력 ZIP도 지정합니다. 이 모드에서는 원본 BRD를 업로드하지 않습니다. 현재 열린 BRD가 대상입니다.
  5. 필요한 레이어/net 범위와 부품 위치/회전 옵션을 선택한 뒤 전송 및 실행을 누릅니다.
저장하지 않은 변경: Agent는 적용 전 현재 설계를 session-before.brd로 저장해 복구 사본을 남기고, 성공하면 result.brd를 별도로 저장하여 해당 결과를 열린 세션에 둡니다. 원래 디스크의 BRD는 덮어쓰지 않습니다. 다만 커밋 후 저장 실패 시 현재 세션이 변경된 상태일 수 있으므로 ZIP의 복구 사본과 로그를 확인하세요.

PID와 실행 파일·생성 시각은 작업 생성, 제출, 명령 전달 단계에서 확인됩니다. PID가 재사용되었거나 대상 창이 없거나 여러 창이 맞으면 작업을 중단하며 다른 창으로 자동 전환하지 않습니다. 취소는 해당 작업에만 요청하며 사용자의 Allegro 프로세스를 종료하지 않습니다.

결과와 다시 받기

결과 ZIP은 항상 새 경로로 받습니다. 성공뿐 아니라 실패 진단용 ZIP도 저장할 수 있습니다.

result.brd성공한 작업이 별도로 저장한 보드입니다. Allegro에서 열어 검토합니다.
result.jsonSKILL 저장 성공/실패/취소 상태와 결과 경로를 담습니다.
generation.log, generation.report.json생성 범위, 지원하지 않는 항목과 형상 통계입니다.
execution.log, runner.logSKILL 실행과 Allegro/Agent 진단 로그입니다.
session-before.brd기존 PID 모드에서 변경 전 현재 설계의 복구 사본입니다.

상태가 interrupted이거나 native_pending=true이면 Allegro 작업의 최종 성공·실패를 아직 확인하지 못했다는 뜻입니다. 이때 완료 미확인 ZIP에는 저장 중일 수 있는 백업 BRD가 포함되지 않을 수 있습니다. 나중에 같은 기존 작업 ID와 새 출력 ZIP 경로를 지정해 기존 작업 받기를 실행하면 상태를 다시 확인하고 최신 ZIP을 받을 수 있습니다.

문제 해결

레이어/NET 입력이나 실행 버튼이 비활성화되어 있습니다

SPD를 아직 읽지 않았거나, 경로를 바꾼 뒤 다시 읽지 않은 상태입니다. 찾아보기…로 파일을 고르면 자동으로 읽고, 직접 입력하거나 저장된 경로라면 SPD 불러오기를 누릅니다. 큰 파일은 로딩이 끝날 때까지 기다립니다. 새 SPD 경로를 지정하면 레이어, NET, 부품 위치/회전 선택이 초기화되므로 목록에서 다시 선택합니다.

연결 확인에 실패합니다

워크스테이션 Agent가 실행 중인지, 노트북에는 실제 워크스테이션 IP와 포트가 입력됐는지 확인합니다. 0.0.0.0은 Agent 바인드 주소이지 노트북 입력값이 아닙니다. 허용 클라이언트 IP를 썼다면 현재 노트북 IP도 목록에 넣습니다. 조직 정책으로 포트 통신이 차단되면 해당 정책에 따라 허용해야 합니다.

PID 확인 또는 PID 실행이 거부됩니다

워크스테이션의 대상 allegro.exe PID인지, Agent와 Allegro가 같은 Windows 로그인 세션 및 권한 수준인지 확인합니다. 창이 여러 개이거나 PID가 종료·재사용된 경우에는 새 PID를 입력해 다시 확인합니다.

출력 ZIP을 받을 수 없습니다

출력은 기존 파일이 아닌 새 경로여야 합니다. 네트워크가 끊겼다면 작업 ID를 보관한 뒤 다시 연결하여 기존 작업 받기를 사용합니다. 업로드는 중간 바이트부터 재개되지 않으므로 새 작업은 처음부터 전송합니다.

취소했는데 Allegro가 즉시 멈추지 않습니다

PID 모드는 SKILL의 안전한 취소 확인 지점에서 취소합니다. 긴 Cadence 함수가 끝날 때까지 지연될 수 있고, 저장 단계 이후 취소는 적용되지 않을 수 있습니다. 사용자의 Allegro 프로세스를 강제 종료하지 않습니다.

지원 범위와 제한

  • 반영 대상은 선택한 layer/net의 SPD plane 형상입니다. 원본 BRD의 규칙, stackup, padstack, routing, via, 부품 정의와 선택하지 않은 객체는 기존 BRD를 기준으로 유지합니다.
  • SPD trace와 via 차이, 부품 생성·삭제, package 변경, 부품 side 변경은 적용하지 않습니다.
  • 부품 위치/회전 옵션은 이미 배치된 부품의 위치와 회전만 다룹니다. 대상 부품이 없거나 배치 상태·면이 맞지 않으면 실행이 실패할 수 있습니다.
  • 실제 Allegro 24.1 라이선스, 현장 설치 환경, SKILL 실행 호환성, 실제 보드 DRC는 자동으로 보증하거나 검증하지 않습니다. 라이선스가 있는 워크스테이션에서 실행하고 결과를 검토해야 합니다.
  • 성공 상태는 전기적 타당성 또는 원본과의 완전한 동등성을 뜻하지 않습니다. 변경한 영역과 void, net, DRC를 Allegro에서 확인하세요.
